# 문서 책임과 테스트 유지 범위

승인 근거: [Issue #474](https://github.com/MyKnow/ssartnership/issues/474), 사용자의 문서 반영·비핵심 테스트 삭제·dev/main 통합 요청. 제품·운영 책임자는 저장소 운영자다.

## 요구와 수용 기준

- AC-001 기존 문서 분류·화면 ID·제품 계약을 보존하고 기획·구현·시점 증거를 분리한다.
- AC-002 대표 탐색/인증/복귀 흐름에서 정책·화면·구현·검증으로 이동할 수 있다.
- AC-003 모든 기존 테스트 파일과 Story의 역할을 분류하고 삭제한 검사에는 사유·잔여 위험을 기록한다.
- AC-004 비핵심 렌더·시각·소스 형태 중복을 제거하고 인증·권한·개인정보·금전·동시성·운영 안전 검증은 유지한다.
- AC-005 실패를 숨기거나 재시도·skip·타임아웃 완화로 통과하지 않는다. 실제 발견 목록과 실행 결과의 일치 검사도 유지한다.
- AC-006 문서·집중 검사·전체 Release, exact-SHA CI, dev 통합 및 main 승격을 구분해서 기록한다.

## 범위와 비목표

[계획](./plan.md), [작업 기록](./tasks.md), [이관표](./migration-map.md)가 실행 경계다. 새 제품 기능·DB 변경·UI 스타일 변경은 포함하지 않는다. 과거 전체 기능의 spec 소급 생성, 조사 없는 사용자 페르소나·성공 목표·보존기간 확정, 별도 문서 플랫폼 도입은 하지 않는다.

공유 정책은 단일 정본에서 관리하고 화면에서는 링크한다. 새 승인 metadata는 추가하지 않고 기존 lifecycle과 Issue 근거를 사용한다. 테스트 삭제는 해당 자동 감지의 의도적 축소이며 모든 UI 회귀를 계속 잡는다는 약속이 아니다.
