# 문서·테스트 정비 실행 계획

## 기준선

문서·테스트 기준은 dev `538b16b4901a9fc41bf870b88c3aa2401f940810`, main `c0e65c34959ca3950ae6b079ed66f133b4eb9fa3`다. 두 tree는 같고 Git 통합 이력은 다르다. 기존 개발자의 변경은 별도 작업트리에 남긴다.

## 순서

1. 전체 문서·테스트 목록과 CI 시간 기준선을 고정한다.
2. 대표 탐색 흐름과 정책 링크를 먼저 정비한다.
3. 제품 개요/흐름의 기술 서술 원본을 보존하고 기존 기술 정본으로 연결한다.
4. 테스트를 파일명만으로 일괄 삭제하지 않고 혼합 파일의 권한·중복 방지 검사를 보존한다.
5. 검사기·배포 수신기의 고정 테스트 개수와 실제 테스트 목록의 관계를 확인한다. 삭제 후 실제 inventory 검증은 유지하고 운영 수신기 호환성을 함께 다룬다.
6. 집중 검사 → 전체 Release → 작업 PR → dev 통합/Preview → dev-main 승격/Production 순서로 검증한다.

## 문서 운영

전수 파일 목록은 이관표에, 변경한 절의 처리·충돌은 별도 표에 기록한다. 승인·검증을 표현하려고 미검증 필드를 자동 채우지 않는다. 위협·수명주기·신뢰성 문서는 기존 규칙의 연결과 미정 사항을 명시한다. 사용자 요구/성공 지표는 개요에 유지하여 빈 문서로 분리하지 않는다.

## 롤백

제품/DB 변경이 없으므로 문제 시 이 작업의 변경만 revert PR로 복구한다. 삭제한 테스트와 원문은 기준선 Git으로 복구 가능하다. 배포 제어 소스 변경은 이전 root-owned 버전과 서비스 설정을 보존하고 되돌릴 수 있어야 한다.
