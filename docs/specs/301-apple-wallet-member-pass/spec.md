# Apple Wallet 회원 인증 패스 제품 명세

## 목표

인증이 완료된 15기 교육생과 운영진이 `/certification`에서 `싸트너십 회원 인증` 패스를 Apple Wallet에 추가하고, 제휴처가 QR을 스캔해 서버의 현재 회원 상태를 확인할 수 있게 한다. Wallet은 기존 30초 웹 인증 QR을 대체하는 신분증이 아니라 더 빠르게 꺼낼 수 있는 보조 수단이다.

## 결정과 비범위

- Apple Wallet `generic` pass만 첫 파일럿에 포함한다.
- 공식 SSAFY 학생증이나 정부·기관 발급 신분증을 표방하지 않는다.
- 수료생, 다른 기수, 쿠폰, NFC, Google Wallet은 범위 밖이다.
- Samsung Wallet은 파트너 신청과 승인 상태 확인까지만 진행하며 실제 발급은 별도 Issue로 분리한다.
- 기존 웹 인증 QR은 주 인증 수단이자 fallback으로 유지한다.

## 사용자 흐름

1. 회원은 비밀번호 변경, 필수 약관 동의, 본인 사진 게이트를 통과하고 `/certification`에 진입한다.
2. Wallet 데이터 이용 내용을 확인하고 `Apple Wallet 패스 발급하기`를 누른다.
3. 서버가 현재 자격을 다시 확인하고 서명된 `.pkpass`를 반환한다.
4. 회원은 iPhone의 Apple Wallet에 패스를 추가한다.
5. 제휴처가 패스의 QR을 스캔한다.
6. 검증 페이지는 현재 회원 상태, 동의, 사진 승인, pass 폐기 여부를 다시 확인해 결과를 표시한다.
7. 회원은 `/certification`에서 패스를 다시 받거나 폐기할 수 있다.

Wallet 데이터 이용 동의의 초기 버전은 `1`이며 저장 항목이나 이용 목적이 바뀌면 버전을 올리고 다시 동의를 받는다. Wallet은 새 필수 게이트가 아니다.

## 표시 정보와 데이터 최소화

패스에는 이름, 기수, 캠퍼스, 역할, `싸트너십 회원 인증`, 비공식 인증 안내만 표시한다. 프로필 사진, 회원 UUID, 이메일, Mattermost 계정·ID, 내부 DB 식별자는 포함하지 않는다.

QR에는 충분히 긴 임의 public ID와 서버 서명만 넣는다. 검증 페이지는 승인된 프로필 사진을 서버에서 별도로 스트리밍할 수 있지만 URL, 로그, 분석 이벤트에는 회원 식별자나 token 원문을 남기지 않는다.

## 자격과 보안 불변조건

발급, 재발급, Wallet 업데이트, QR 검증은 모두 같은 현재 상태를 기준으로 한다.

- 로그인한 활성 회원이며 비밀번호 변경이 필요하지 않아야 한다.
- 현재 필수 정책 동의와 본인 사진 승인을 완료해야 한다.
- 15기 교육생 또는 운영진이어야 한다.
- pass가 폐기 상태가 아니어야 한다.
- 패스가 기기에 남아 있어도 현재 상태가 부적격 또는 폐기면 검증 결과는 무효다.
- QR, Apple 인증 token, 인증서 private key, device push token을 로그나 공개 클라이언트에 노출하지 않는다.
- Apple의 `sharingProhibited`는 보조 방어이며 캡처·공유 방지 보장으로 취급하지 않는다.
- 공개 검증 응답은 `no-store`, `noindex`를 사용하고 token 열거를 어렵게 한다.

세부 저장·키 파생·adapter·운영 설계는 [기술 계획](./plan.md)에서 관리한다.

## UI 계약

- `/certification`의 기존 인증 카드가 먼저 보이고 Apple Wallet 카드는 그 아래, 계정 관리 액션 위에 배치한다.
- `미발급`, `발급됨`, `재동의 필요`, `회수됨`, `오류` 상태와 다음 행동 하나를 보여준다.
- 저장 snapshot이 현재 회원 정보와 다르면 `다시 받기`를 제공한다.
- 선행 조건 미충족 시 발급 CTA 대신 원인에 맞는 `설정하러 가기`를 보여준다.
- 360px에서는 한 열과 전체 너비 CTA, 820px 이상에서는 설명과 액션을 두 영역으로 배치한다.
- 상태는 색만으로 표현하지 않고 text badge와 설명을 함께 제공한다.

## 수용 기준

- 회원별 발급·재발급·폐기가 중복 요청에도 일관된 결과를 만든다.
- QR 변조·열거·폐기·현재 자격 변경이 안전하게 거절된다.
- Apple device 등록·해제·변경 serial 조회·최신 pass 다운로드가 PassKit 인증 경계를 지킨다.
- 기존 회원 게이트와 웹 인증 QR이 회귀하지 않는다.
- 발급·설치·검증·폐기·동기화 관측값에는 credential 원문이나 회원 식별자가 없다.
- 360/820/1366px에서 상태와 단일 다음 행동이 보이며, 실제 iPhone에서 추가·삭제·재추가·정보 변경·폐기 후 스캔을 검증한다.
