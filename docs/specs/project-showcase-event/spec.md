# SSAFY 프로젝트 쇼케이스·체험 이벤트

승인 근거: 15기 서울 지역대표 9월 기획안 v4 「내 프로젝트를 소개합니다! — 서비스 홍보·체험 이벤트」(2026-09-08)와 [Issue #480](https://github.com/MyKnow/ssartnership/issues/480). 기획안에 없는 세부 운영 기준은 2026-09-26 운영 책임자 결정으로 확정했다. 기획안과 이 문서가 충돌하면 기획안의 운영 의도를 우선하고 이 문서를 고친다.

## 목적

SSAFY 구성원이 직접 개발·배포한 서비스를 홍보하고, 구성원이 여러 서비스를 체험하며 관심 표시와 피드백을 남기게 한다. 출품 참여자와 체험 참여자를 대상으로 무작위 추첨 경품을 제공한다.

## 일정과 단계

- 페이지 완성 후 모집 1주, 체험·피드백 1주를 운영하고, 체험 종료 뒤 검증·추첨을 거쳐 결과를 발표한다.
- 날짜는 코드에 고정하지 않고 운영자가 `Asia/Seoul` 기준으로 설정한다.
- 단계: 준비 → 모집 → (검수 대기) → 체험 → 검증·추첨 → 발표 → 종료. 운영자가 이벤트를 비활성화하면 날짜와 관계없이 일시 중지 상태가 된다.
- 단계 사이 공백에는 다음 일정을 안내한다. 운영자 비활성화와 일정상 공백은 다른 문구로 구분한다.

## 경품

| 분야 | 경품 | 최대 수량 | 선정 단위 |
| --- | --- | --- | --- |
| 출품 | 배달의민족 상품권 10,000원 | 20건 | 유효 출품 프로젝트 1건 = 추첨 1건, 당첨 시 대표자에게 Mattermost로 1회 발송 |
| 체험 | 메가커피 아이스 아메리카노 교환권 1매 | 25명 | 체험 참여자, 보유 추첨권 수에 비례한 가중 추첨, Mattermost로 발송 |

- 선정 수량은 운영자가 설정하며 기본값은 출품 20, 체험 25다. 대상이 수량보다 적으면 대상 전원을 선정하고 잔여 경품은 미집행한다.
- 관심 표시 수, 조회 수, 피드백 수, 인기 순위는 경품 선정에 영향을 주지 않는다.

## 요구와 수용 기준

### 출품

- AC-001 캠퍼스·기수 제한 없이 SSARTNERSHIP 회원 인증을 마친 구성원은 모집 기간에 개인 또는 팀으로 출품할 수 있다.
- AC-002 유형은 WEB, APP, GAME, EMBEDDED다. WEB·APP·GAME은 배포·운영 중인 서비스의 `https` 주소를 받는다. APP은 스토어 또는 다운로드 안내 주소이고, GAME은 웹 게임 또는 스토어 주소다. EMBEDDED는 허용된 영상 호스트(YouTube, Vimeo)의 시연 영상 주소를 받는다.
- AC-003 공통 입력은 서비스명, 한 줄 소개, 상세 설명, 대표 홍보 이미지, 참여자 이름·학번이다. 참여자가 2명 이상이면 팀명을 필수로 받는다. 제출자(대표자)는 회원 이름과 일치하는 이름과 본인 학번으로 참여자 명단에 포함돼야 한다.
- AC-003a 학번은 숫자 7자리다. 앞 2자리는 기수(현재 15, 16 예정)이고 나머지 5자리는 숫자다. 기획안의 기수 제한 없음 원칙에 따라 특정 기수 값으로 제한하지 않는다. 출품 참여자와 체험 참여 등록에 같은 검증 규칙을 사용한다.
- AC-004 참가자 1인당 출품 프로젝트는 1개다. 한 회원은 이벤트에서 대표자로 1건만 제출할 수 있고, 같은 학번은 이벤트 안에서 두 프로젝트의 참여자 명단에 들어갈 수 없다.
- AC-005 제출자는 팀원에게 이름·학번의 이벤트 운영 사용을 안내하고 동의를 받았음을 확인해야 한다. 또한 당첨 시 대표자 이름·학번 일부를 가려 공지하는 데 동의해야 한다. 두 동의 모두 출품 필수 조건이다.
- AC-006 운영자는 개발 참여 여부, 링크 접속, 필수 자료를 확인해 승인, 수정 요청, 반려, 숨김으로 검수한다. 승인된 출품만 유효 출품이다.
- AC-007 출품자는 자기 출품작의 제출 내용, 검수 상태, 운영자 검수 사유를 볼 수 있다. 수정 요청을 받으면 모집 기간 안에 수정해 다시 제출할 수 있다. 모집 기간 안에는 출품을 취소할 수 있다.
- AC-008 외부 서비스에 SDK, 추적 코드, API 연동, 응답 헤더 변경을 요구하지 않는다. 외부 서비스 안에서의 실제 사용이나 앱 설치를 확인했다고 표현하지 않는다.

### 체험·피드백

- AC-009 체험 기간에만 승인된 출품의 목록과 상세를 공개한다. 목록은 검색, 유형 필터, 최신순·이름순 정렬을 지원한다. 로그인하지 않아도 목록과 상세는 볼 수 있다.
- AC-010 체험 기간 밖에서 상세 주소로 들어오면 프로젝트 내용 없이 "체험 기간이 아니에요" 안내와 이벤트 일정, 이벤트 페이지 링크를 보여 준다.
- AC-011 체험 참여자는 첫 체험 전에 이벤트 참여 등록을 한 번 한다. 참여 등록은 본인 학번 입력, 학번의 이벤트 운영 사용 동의, 당첨 시 이름·학번 일부를 가려 공지하는 데 대한 동의로 구성되며 모두 필수다.
- AC-012 참여 등록한 회원이 체험 시작을 누르면 서버 시각으로 체험 시작을 기록하고 외부 주소를 새 탭으로 연다. 자기 프로젝트는 체험할 수 없다.
- AC-013 체험 시작 후 서버 시각 기준 60초가 지나면 해당 프로젝트에 한 줄 피드백(10자 이상 300자 이하)을 제출할 수 있다. 60초가 지나기 전에는 제출할 수 없고 남은 시간을 안내한다. 피드백 제출을 마친 프로젝트 1건을 유효 체험 1건으로 인정한다. 프로젝트당 피드백은 1회만 제출한다.
- AC-014 관심 표시는 체험 기간 동안 로그인 회원이 프로젝트마다 켜고 끌 수 있으며 추첨권과 무관하다. 자기 프로젝트에는 관심 표시를 할 수 없다.
- AC-015 체험 추첨권은 유효 체험이 1건 이상인 회원에게만 부여한다. 보유 추첨권 = 유효 체험 프로젝트 수다. 유효 체험이 없으면 0장이다. 같은 프로젝트의 반복 체험과 반복 제출은 추가 추첨권이 되지 않는다.
- AC-016 인증 회원의 프로젝트 상세 최초 조회를 고유 조회로 집계한다. 출품자 본인과 운영자 조회, 반복 새로고침은 집계하지 않는다.

### 출품자 전달

- AC-017 출품자는 자기 프로젝트의 고유 조회, 체험 시작, 유효 체험, 관심 표시 수와 피드백 본문을 볼 수 있다. 피드백에는 작성자 이름, 학번, 회원 ID, 작성 시각 같은 식별 정보를 붙이지 않는다.
- AC-018 운영자는 욕설, 개인정보 노출 등 부적절한 피드백을 숨길 수 있다. 숨긴 피드백은 출품자에게 보이지 않지만 이미 인정된 유효 체험은 유지한다.

### 검증·추첨·발표

- AC-019 체험 종료 후 운영자는 추첨 후보 목록(출품 후보 프로젝트, 체험 후보와 보유 추첨권)을 확인하고 외부인, 중복 계정, 허위 체험 기록을 사유와 함께 후보에서 제외할 수 있다. 제외와 복구는 감사 기록에 남긴다.
- AC-020 추첨은 출품 분야를 먼저, 체험 분야를 나중에 실행한다. 출품 추첨은 유효 출품 프로젝트 중 균등 무작위, 체험 추첨은 보유 추첨권 가중 무작위(동일인 중복 선정 없음)다. 추첨은 서버의 CSPRNG로 수행한다.
- AC-021 1인 1경품: 출품과 체험을 통틀어 한 회원은 경품을 최대 1개 받는다. 출품 당첨 프로젝트의 대표자는 체험 추첨 후보에서 제외한다.
- AC-022 운영자는 당첨을 사유와 함께 무효 처리하고 1명(1건)을 재추첨할 수 있다. 사유는 중복 당첨, 경품 수령 불가(Mattermost 연락 불가 등), 검증 실패다. 원 당첨과 재추첨은 모두 원장에 남긴다. 재추첨할 후보가 없으면 그 경품은 미집행한다.
- AC-023 추첨은 검증·추첨 단계에서 실행하고, 결과는 발표 시작 시각부터 공개한다. 공개 페이지는 출품 당첨을 프로젝트명과 대표자 마스킹 표시로, 체험 당첨을 마스킹 표시로 보여 준다. 마스킹 규칙은 이름의 첫 글자 뒤에 `**`(예: `정**`), 학번은 앞 2자리(기수)와 뒤 2자리만 남기고 가운데 3자리를 고정 길이 `****`로 가린다(예: `1512343` → `15****43`).
- AC-024 운영자 화면은 당첨 결과를 Mattermost 공지에 붙여 넣을 수 있는 텍스트로 복사하는 기능을 제공한다. 공지 게시는 운영자가 직접 한다.
- AC-025 당첨자는 로그인 후 내 참여 화면에서 자기 당첨 여부와 경품을 확인한다. 경품은 운영자가 당첨자의 Mattermost 계정으로 발송하며 별도 연락처는 수집하지 않는다. 운영자는 당첨별 발송 완료를 기록한다.

### 개인정보·보안

- AC-026 참여자·체험자 이름, 학번, 개별 체험·피드백 작성 기록은 서버 service role로만 접근한다. 공개 조회, 출품자 화면, 공개 API 응답에는 AC-023의 마스킹 값 외에는 포함하지 않는다.
- AC-027 입력 검증, 단계, 소유권, 1인 1출품, 60초 경과, 중복 체험·피드백·추첨 방지는 서버와 DB 경계에서 강제한다. FE와 BE는 같은 검증 모듈을 사용한다.
- AC-028 운영자는 `/admin/events/project-showcase`에서 일정·수량 설정, 상태별 전체 출품 목록과 검수, 피드백 숨김, 후보 검증, 추첨, 무효·재추첨, 발송 완료와 이벤트 정산 완료 처리를 한다. `/admin/events/project-showcase/logs`에서 활동과 집계를 시간 역순으로 본다. 로그 응답에는 학번, 회원 ID, IP, User-Agent를 넣지 않는다.
- AC-029 운영자가 이벤트 정산 완료를 기록하면 30일 뒤 예약 작업이 참여자·체험자 학번, 참여 등록, 체험·피드백·관심 기록과 회원의 연결, 추첨 원장의 회원 연결을 파기한다. 출품자에게 전달된 익명 집계와 피드백 본문, 추첨 원장의 마스킹 값·수량·시각은 증빙으로 남긴다. 파기 실행은 감사 기록에 남긴다.

## 화면 구조

```text
/events/project-showcase                    이벤트 허브
  히어로 → 상태 카드(단계, 다음 일정, 단계별 주요 버튼, 내 참여)
  → 일정 3단계 → 참여 방법·경품·유의사항(항상 표시) → 단계별 본문
     모집: 출품 가이드 / 체험: 프로젝트 갤러리(체험 완료 배지) / 발표: 당첨 결과
/events/project-showcase/projects/new       출품
/events/project-showcase/projects/[id]      상세·체험·피드백 (기간 밖에는 안내 화면)
/events/project-showcase/my                 내 참여: 내 출품, 체험·추첨권, 당첨 결과
/events/project-showcase/my/projects/[id]   내 출품 보기·수정·취소, 검수 사유, 받은 피드백

/admin/events/project-showcase              운영
/admin/events/project-showcase/logs         로그·집계
```

- 상태 카드의 주요 버튼은 단계를 따른다. 모집 기간은 출품하기, 체험 기간은 프로젝트 둘러보기, 발표 기간은 결과 확인이다.

## 범위 밖

외부 서비스 소스 수정, 외부 서비스 안의 실제 이용 시간·클릭·설치 측정, 프로젝트 품질 평가와 순위 시상, 체험 기간 밖 프로젝트 내용 공개, 마스킹하지 않은 이름·학번 공개, 공개 원시 활동 로그, Mattermost 공지 자동 게시.
