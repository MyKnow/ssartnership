# 사용자 흐름

내부 호출·테이블 목록은 [API](../architecture/api-and-integrations.md)와 [데이터 모델](../architecture/data-model.md), 과거 상세 기술 서술은 [보존 원본](../history/2026-09-20-product-user-flows.md)에 둔다. 아래 흐름은 사용자 과업과 실패 복구를 다룬다.

## 제휴 탐색 흐름

<a id="flow-discovery-001"></a>
**FLOW-discovery-001**: 홈에서 캠퍼스·카테고리·검색·정렬·대상을 선택하고 제휴 상세로 이동한다. 검색 제출과 필터 변경은 URL 상태를 보존하며 뒤로가기 시 원래 탐색 맥락으로 돌아간다. 결과가 없으면 조건을 해제·수정할 수 있어야 한다.

대외비 상세나 회원 행동에는 로그인이 필요하다. 회원 필수 단계를 완료한 뒤 안전한 원래 목적지로 돌아간다. 비공개 제휴·자격 미충족을 로그인만으로 우회할 수 없다. 혜택 노출과 접근은 [공유 정책](./policies/access-and-benefits.md)을 따른다. 구현·검증 연결은 같은 정책 문서의 표를 참조한다.

## 캠퍼스별 탐색 흐름

캠퍼스 탐색에서 해당 캠퍼스의 제휴를 확인한다. 미지원 경로는 정상 목록으로 오인시키지 않고 오류·복구 경로를 제공한다. 캠퍼스 추론과 SEO 처리의 기술 정본은 [시스템](../architecture/system-overview.md)과 [IA](./information-architecture.md)다.

## 회원 가입과 직접 Mattermost 흐름

사용자는 가입 경로에서 대상 기수와 가능한 인증 수단을 선택한다. 인증 실패·만료·재전송 제한은 안전한 안내와 허용된 재시도 경로를 제공한다. 수료생 증명서 신청과 기존 회원 복구는 [수료생 계약](./screen-specs/graduate-verification.md)으로 연결한다. 코드 유효시간 같은 운영 수치를 여기서 중복 고정하지 않는다.

## 회원 로그인과 정책/비밀번호 강제 흐름

로그인 후 필요한 비밀번호 변경·약관·이메일·사진 단계를 공용 게이트 순서대로 진행하고 원래 과업으로 돌아간다. 외부 URL이나 자기 게이트로 반복 복귀하지 않는다. 단계 순서와 예외는 [공유 정책](./policies/access-and-benefits.md), 화면별 입력·오류는 [인증 화면](./screen-specs/auth.md)을 따른다.

## 비밀번호 재설정 흐름

회원은 재설정 화면에서 허용된 인증 수단을 선택한다. 사용할 수 없는 수단은 숨기거나 사유를 알리고, 기존 계정 복구가 필요한 경우 해당 신청으로 연결한다. 파트너는 재설정과 필수 비밀번호 변경을 거친다. 완료·만료·잘못된 토큰을 구분하고, 토큰이나 계정 존재 여부 등 민감 정보를 오류에 노출하지 않는다.

## 인증 카드와 QR 검증 흐름

회원은 인증 카드에서 QR을 표시한다. 검증자는 유효성·만료·회원 상태에 따른 성공 또는 실패 안내를 받는다. 이미지 열람과 토큰 발급 권한을 구분한다. [공개·회원 화면](./screen-specs/public-and-member.md)과 [인증 화면](./screen-specs/auth.md)이 상태별 계약이다.

## 리뷰/즐겨찾기/쿠폰 흐름

회원은 상세에서 리뷰·즐겨찾기·쿠폰 행동을 수행한다. 입력·업로드 실패를 안내하고 중복 제출과 잘못된 재시도를 막는다. 쿠폰 자격·기간·사용 한도·동시성은 [쿠폰 운영](./guides/partner-coupon-operations.md)을 따른다. 미승인 상태를 성공으로 표현하지 않는다.

## 파트너사·제휴처 등록 신청 흐름

파트너는 신청서를 작성하고 오류 필드를 수정한 뒤 제출한다. 운영자는 신청을 검토해 회사·계정·제휴로 전환하고 필요한 초기 설정 안내를 전달한다. 검토·발송 실패는 신청 성공과 구분한다. FE/BE 검증은 같은 규칙을 사용한다.

## 파트너 포털 흐름

초기 설정 또는 로그인 후 연결 회사가 여럿이면 회사를 선택한다. 담당자는 해당 회사의 제휴·메트릭·리뷰·플랜·알림·지원으로 이동한다. 변경 요청의 즉시 반영과 승인 대기, 중복 요청 제한, 거절 후 복구는 [파트너 화면](./screen-specs/partner.md)의 계약을 유지한다.

## 관리자 운영 흐름

관리자는 인증 후 권한과 배정 범위 내 업무만 수행한다. 목록 탐색 → 상세 → 변경/검토 → 결과 확인으로 이어지고, 실패 시 입력·검색 맥락을 보존한다. 민감 작업의 확인·권한·감사 기록은 [관리자 화면](./screen-specs/admin.md), [접근 제어](../security/admin-access-control.md)를 따른다.

## 알림과 Push 흐름

사용자는 알림 목록을 확인하고 구독·수신 설정을 변경한다. 운영자는 대상·내용을 확인하고 발송 결과를 확인한다. 발송 요청 접수와 실제 외부 전달 성공은 구분한다. 실패·재전송·감사 경계는 [API](../architecture/api-and-integrations.md)와 [로깅](../architecture/event-logging.md)에 연결한다.
