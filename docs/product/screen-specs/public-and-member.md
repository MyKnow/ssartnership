# 공개·회원 화면 계약

작성 기준일: 2026-07-10

## 모바일 공용 탐색

- `768px` 미만에서 하단 탐색이 보이면 상단 헤더에는 브랜드·테마 전환과 로그인 회원의 알림을 유지한다. 같은 구간의 Footer에서는 테마 전환과 알림센터를 숨겨 중복을 제거한다. 하단 탐색이 없는 집중 흐름과 데스크톱 Footer는 기존 설정 진입점을 유지한다.
- 하단 탐색은 좌측의 `홈·쿠폰함·내 정보` 묶음과 우측의 독립 검색 섬으로 구성한다. 검색은 홈의 혜택 검색 입력으로 이동해 즉시 입력할 수 있게 한다.
- `내 정보`는 공용 탐색의 상위 용어이며 `/certification` 화면 안에서는 현장 제시 기능의 고유 제목인 `내 인증`을 유지한다.
- 비로그인 사용자가 쿠폰함 또는 내 정보를 선택하면 목적별 인증 안내에서 로그인·회원가입을 선택할 수 있게 하고, 목적지를 `returnTo`로 보존해 인증 후 해당 화면으로 이동한다. 인증·복구·검증 집중 흐름과 모바일 sticky CTA가 있는 파트너 상세에서는 하단 탐색을 노출하지 않는다.
- iOS 계열의 glass 표현은 하단 탐색, 모바일 sticky action, 일시적 overlay Toast에만 제한하고, safe area·본문 하단·고정 액션과 겹치지 않게 배치한다. sticky action 안에서는 primary의 브랜드 대비를 유지한다.
- 공개·회원 페이지 사이를 전환할 때 본문 스켈레톤과 무관하게 하단 탐색을 유지하고, 전환 완료 후 도착 경로에 맞는 활성 항목을 표시한다.

## `/` — 이벤트와 혜택 탐색 시작

- 목표·위계: 대표 이벤트 → 혜택 디렉터리의 검색 → 카테고리/고급 필터 → 결과 요약 → 제휴처 목록 순으로 읽힌다.
- 액션·흐름: primary는 대표 이벤트 참여이며 혜택 탐색은 별도 CTA를 반복하지 않고 검색 입력에서 바로 시작한다. 상세는 query 없는 canonical URL로 열고, 브라우저 뒤로가기 시 history에 남은 `q`, `category`, `campus`, `audience`, `sort`, `view`를 복원한다.
- 경계·상태: 공개 repository와 회원의 campus/year만 사용한다. 기본, 빈 결과, 로딩, 오류, 긴 한국어, 프로모션 없음 상태를 제공한다.
- 반응형·분석: Compact `<600`은 단일 pane, Medium `600–839`는 상단 필터와 최대 2열 결과, Expanded `840–1199`는 필터 sidebar와 결과 pane, Large `1200–1599`는 sidebar와 최대 2열 비교, Extra Large `1600 이상`은 wide container 최대 폭을 유지한다. `page_view`, `home_banner_click`, `benefit_directory_start`, `directory_view_change`를 기록한다.
- 수용 기준: 대표 이벤트는 캐러셀 위에 별도 가시 제목·설명을 반복하지 않고, 뷰포트 전체 폭의 radius 없는 21:9 직사각형으로 시작한다. 캐러셀 직후에는 알림 설정 배너 없이 `제휴 혜택 찾기`의 짧은 섹션 헤더와 구분선으로 혜택 디렉터리를 시작한다. 검색이 카테고리보다 먼저 오고 설명 없는 compact category chip을 쓴다. Compact에서는 검색과 중앙 정렬된 `필터 펼쳐보기`만 기본 노출한다. 이 버튼은 44px 이상의 조작 영역과 `aria-expanded`를 제공하며, 펼치면 카테고리·캠퍼스·적용 대상을 인라인으로 보여 주고 다시 접을 수 있다. 이 시범 UI에서는 닫힌 상태에 선택 조건의 요약을 표시하지 않는다. 검색어·카테고리의 중복 적용 칩은 노출하지 않으며, 정렬은 결과 수와 같은 행에서 바꾼다. 필터 값은 URL query가 단일 기준이다. Expanded 이상에서는 검색·카테고리·상세 필터 sidebar를 유지한다. 카드형은 혜택 최대 2개와 `+N`, 대상 요약, 위치, 상세, 즐겨찾기를 유지하고 카드 표면 클릭으로도 상세에 진입한다. 카테고리·즐겨찾기·내부 링크는 각 고유 동작을 유지한다. 리스트형은 모바일·태블릿에서 혜택/대상을 생략하고 Large 데스크톱부터 비교 정보로 노출한다. Compact 리스트는 썸네일·핵심 정보·상세 아이콘을 한 행에 유지하고 44px 조작 영역을 보존한 채 이미지·글자·간격을 축소한다.

## `/campuses/[campus]` — 캠퍼스별 혜택 탐색

- 목표·위계: 캠퍼스 이름과 결과 요약 → 검색/카테고리 → 제휴처 목록 순이다.
- 액션·흐름: primary는 제휴처 상세 열기, 보조는 다른 캠퍼스·필터 변경이다. 홈과 상세 양쪽에서 진입하고 필터가 적용된 목록으로 복귀한다.
- 경계·상태: 유효 campus slug와 공개 가능한 제휴처만 조회한다. 기본, 빈 캠퍼스, 잘못된 slug, 로딩, 오류, 긴 목록을 제공한다.
- 반응형·분석: 모바일은 한 열과 compact chip, 태블릿·데스크톱은 결과 grid를 사용한다. `campus_page_view`, `partner_card_click`을 campus와 함께 기록한다.
- 수용 기준: campus가 URL과 metadata에 일치하고 320px에서 chip·카드가 수평 overflow를 만들지 않는다.

## `/events/[slug]` — 이벤트 상세·참여

- 목표·위계: 이벤트 상태/제목 → 핵심 보상과 기간 → 참여 조건 → 참여 CTA → 상세 안내 순이다.
- 액션·흐름: primary는 참여 또는 대상 과업 실행이며 보조는 혜택 탐색 복귀다. 당첨자만 winner form으로 분기한다.
- 경계·상태: 공개 이벤트와 로그인 회원의 참여·보상 상태를 조합한다. 진행 전, 진행 중, 종료, 참여 완료, 보상 대기, 오류를 제공한다.
- 반응형·분석: 모바일 CTA는 내용 뒤에 묻히지 않게 sticky 또는 근접 배치한다. `event_view`, `event_cta_click`, `event_participation_complete`를 기록한다.
- 수용 기준: 종료 이벤트에서 참여 CTA가 비활성 사유를 말하고, 동일 이벤트의 중복 참여 규칙이 UI와 서버에서 일치한다.

## `/legal/[kind]` — 정책 문서 확인

- 목표·위계: 문서 종류·버전·시행일 → 본문 → 이전 버전 이동 순이다.
- 액션·흐름: primary는 문서 읽기이며 별도 전환 CTA를 만들지 않는다. 로그인·가입 동의 화면과 footer에서 진입하고 이전 화면으로 복귀한다.
- 경계·상태: 공개된 policy repository만 사용한다. 최신/지정 버전, 없는 종류, 없는 버전, 로딩·오류 상태를 제공한다.
- 반응형·분석: 본문은 좁은 읽기 폭과 안정된 heading anchor를 쓴다. `policy_view`에 kind/version을 기록한다.
- 수용 기준: URL version과 표시 버전이 같고 긴 링크·표가 320px viewport를 밀지 않는다.

## `/partner-registration` — 제휴 등록 신청

- 목표·위계: 현재 단계와 첫 입력 → 필수 항목 → 다음/제출 → XLSX·가이드 disclosure 순이다.
- 액션·흐름: primary는 단계 진행 또는 최종 제출 하나이며 보조는 이전 단계와 임시 입력 유지다. 공개 헤더·파트너 안내에서 진입하고 접수 완료 상태로 이탈한다.
- 경계·상태: FE와 server action이 같은 validation 규칙을 사용한다. web 입력/XLSX, validation error, 업로드 오류, 제출 중, 성공, 중복 제출을 제공한다.
- 반응형·분석: 모바일은 `1/5 제휴처` compact stepper, 데스크톱은 진행률과 입력을 나란히 두되 입력이 가이드보다 먼저 온다. `registration_start`, `registration_step_complete`, `registration_submit`을 기록한다.
- 수용 기준: 첫 오류에 focus되고 새로고침 전 단계 데이터가 보존되며, XLSX와 긴 설명은 기본 흐름을 가리지 않는다.

## `/partners/[id]` — 제휴 혜택 이용

- 목표·위계: 제휴처 이름·이용 기간 → 소개 → 핵심 혜택 → 이용 CTA·인증 상태 → 조건/대상 → 지점·리뷰 → 갤러리/태그 순이다.
- 액션·흐름: primary는 혜택 이용이며 보조는 즐겨찾기, 지도, 문의, 리뷰다. 목록에서 진입할 때는 query 없는 canonical 상세 URL을 사용하고 브라우저 history로 목록 상태에 복귀한다. 로그인·인증·쿠폰처럼 실제 복귀가 필요한 상세 내부 흐름만 현재 상세 경로를 안전한 return context로 사용한다.
- 경계·상태: visibility, 기간, benefit visibility, member eligibility를 서버에서 판정한다. 공개, 로그인 필요, 대상 아님, 만료, not-found, 이미지 오류, 리뷰 없음 상태를 제공한다.
- 반응형·분석: 모바일은 하단 탐색을 숨기고 safe area 하단에 sticky action bar 하나만 고정하며, 본문 끝에는 이 CTA에 가려지지 않는 여백을 둔다. 공유 등 일시적 피드백 toast는 모바일 sticky action bar와 데스크톱 FAB 상단에서 최소 16px 떨어뜨려 액션을 가리지 않는다. 복사 가능한 연락처 정보도 본문에 표시한다. 상단 식별 카드는 `480px` 미만 compact 화면에서 큰 정사각형 썸네일을 먼저 전체 폭으로 보여 주고, 카테고리·즐겨찾기·공유·제휴처명·날짜 identity cluster를 그 아래에 배치한다. `480px` 이상에서는 썸네일과 identity cluster를 나란히 두고, 썸네일의 한 변은 카테고리부터 날짜까지 identity cluster의 실제 높이를 따른다. identity cluster는 작은 카테고리 점·라벨, 제휴처명, 달력 아이콘과 평문 날짜 순으로 읽히며 카테고리와 날짜를 chip으로 만들지 않는다. 즐겨찾기와 공유만 하나의 작은 utility dock으로 분리해 카테고리 행 오른쪽에 둔다. 제목과 날짜 사이는 16px 이하의 짧은 리듬을 유지하며, 기간에는 별도 `이용 기간` 가시 라벨을 반복하지 않고 긴 소개 본문은 헤더에 넣지 않는다. 넓은 화면은 혜택 이용 CTA를 핵심 혜택 카드 최하단의 full-width primary action으로 둔다. 추가 이미지는 모바일에서 대표 이미지 아래의 가로 썸네일 목록을 유지하고, 모든 크기에서 좌우 스와이프로 다음·이전 이미지를 이동한다. 태블릿 이상에서는 선택 이미지를 전체 폭의 중앙 약 65% 크기로 두고, 이전·다음 방향의 최대 세 이미지는 약 70% 이하 크기의 안개 미리보기 더미로 양옆 뒤에 겹쳐 둔다. 카드가 멀수록 더 작고 옅어지며 바깥쪽에 조금만 드러난다. 첫·마지막 이미지에서는 없는 쪽 미리보기와 화살표를 함께 숨긴다. 태블릿 이상의 양끝 화살표는 이동 가능한 쪽에만 보이며 자동 순환하지 않는다. 이용 조건은 핵심 혜택 목록 바로 아래에 같은 섹션 제목과 번호가 있는 inset 목록 템플릿으로 둔다. 연락처·위치·대상은 `세부 정보` 그룹으로 묶는다. `partner_detail_view`, `benefit_cta_click`, 지도·문의·예약 클릭을 기록한다.
- 수용 기준: 잠긴 혜택은 민감 조건과 URL을 노출하지 않고, CTA는 한 화면에서 중복 primary로 보이지 않는다. 일반 상세 URL에는 목록용 `returnTo`를 노출하지 않으며 브라우저 뒤로가기에서 기존 필터를 복원한다. 소개가 있으면 핵심 혜택 바로 위의 단일 inset surface에서 전문을 표시하고, 소개가 없으면 제목과 surface를 함께 생략한다. 태그는 하단 `태그` 제목 아래에 별도 컨테이너와 중복 라벨 없이 모두 표시한다. 소개와 태그에는 accordion을 사용하지 않는다. 공개 혜택은 번호가 있는 핵심 목록과 같은 위계의 이용 조건 목록을 바로 이어 읽히고, 연락처·위치·대상은 한 단계 낮은 정보 그룹으로 둔다. 위치와 적용 대상은 화면 폭과 관계없이 각각 한 행과 독립된 surface로 분리하고 사이에 여백을 둔다. 운영진·교육생·수료생은 항상 함께 표시하되 적용 대상만 강조한다.

## `/partners/[id]/benefit-use` — 오프라인 상시 혜택 이용 확인

- 목표·위계: 회원의 SSAFY 인증 카드 → 선택한 혜택과 제휴처 → 제휴처 확인 PIN → 이용 확인 결과 순이다.
- 액션·흐름: 제휴처 상세의 `혜택 이용하기`에서 혜택을 선택하고 진입한다. 제휴처 담당자가 인증 카드와 PIN을 확인한 뒤 한 번의 확인 요청으로 이용을 기록한다. 상세 복귀 경로는 안전하게 보존한다.
- 경계·상태: 로그인 회원, 오프라인 제휴처, 활성 제휴 기간, 등록된 혜택, 서버에 저장된 PIN hash를 모두 재검증한다. 비로그인, 잘못된 혜택, PIN 형식/불일치, 기간 만료, 처리 중, 완료 상태를 제공한다.
- 반응형·분석: 인증 카드는 독립된 카드로 표시하고 PIN 입력 카드는 별도 surface로 둔다. 320px에서도 카드와 PIN 입력이 가로 overflow를 만들지 않는다. 혜택 선택, PIN 시도, 성공·실패, 실제 이용 기록을 서로 다른 이벤트로 기록한다.
- 수용 기준: PIN 원문과 이용 ID를 URL·분석 속성·사용자 메시지에 노출하지 않는다. 동일 idempotency key 재시도는 실제 이용 집계를 중복시키지 않으며, 성공 후 버튼은 중복 제출을 막는다.

## `/suggest` — 제휴처 제안

- 목표·위계: 제안 목적 → 제휴처 이름/근거 → 연락·위치 보조 정보 → 제출 순이다.
- 액션·흐름: primary는 제안 제출, 보조는 홈 복귀다. 혜택 탐색의 빈 결과·footer에서 진입하고 성공 확인으로 이탈한다.
- 경계·상태: 공개 입력을 같은 FE/BE schema로 검증하고 rate limit한다. 기본, validation error, 제출 중, 성공, 서버 오류를 제공한다.
- 반응형·분석: 한 열 form과 짧은 도움말을 사용한다. `suggest_start`, `suggest_submit`만 비식별 필드로 기록한다.
- 수용 기준: 연락처 등 민감 입력은 로그에 남지 않고 첫 오류 focus와 재시도 시 입력 보존이 동작한다.

## `/support/bug-report` — 문제 제보

- 목표·위계: 문제 유형 → 자동 생성 재현 템플릿 → 복사/mailto 안내 순이다.
- 액션·흐름: primary는 템플릿 복사, 보조는 메일 앱 열기와 홈 복귀다. footer·오류 화면에서 진입한다.
- 경계·상태: 브라우저 정보는 사용자가 확인할 수 있는 범위만 포함한다. 기본, 긴 URL, 복사 성공/실패, mailto 미지원 상태를 제공한다.
- 반응형·분석: 코드형 템플릿은 줄바꿈 가능하고 모바일 버튼은 세로 배치한다. `bug_report_template_copy`를 기록한다.
- 수용 기준: token·cookie·개인정보가 템플릿에 자동 포함되지 않고 320px에서 긴 URL이 overflow되지 않는다.

## `/certification` — 내 인증

- 목표·위계: 인증 유효 상태 → 구성원 이름/기수/캠퍼스 → QR·만료 → Apple Wallet 보조 인증 수단 순이다. 계정 변경 기능은 별도 `/settings` 화면에서 관리한다.
- 액션·흐름: primary는 QR 제시 또는 갱신이다. 기존 필수 게이트를 통과한 15기 교육생·운영진은 보조 액션으로 Wallet 데이터 이용에 동의하고 `싸트너십 회원 인증` 패스를 추가·재발급·폐기할 수 있다. 사용자 메뉴에서 진입하고 원래 `returnTo`로 복귀할 수 있다.
- 경계·상태: member session, 서버 발급 QR, Wallet pass repository의 현재 상태만 사용한다. 웹 QR의 유효·갱신 중·만료·발급 오류와 Wallet의 미발급·발급됨·회수됨·오류·설정 필요 상태를 제공한다. Wallet QR 검증은 pass 스냅샷이 아니라 현재 회원·필수 동의·사진·폐기 상태를 다시 확인한다.
- 반응형·분석: QR은 모바일 현장 제시를 우선한다. Apple Wallet 상태 카드는 인증 카드 아래의 낮은 강조 surface로 두고 360px에서는 한 열과 full-width CTA, 820px 이상에서는 설명과 액션을 나눈다. `certification_view`, `certification_refresh`, `wallet_pass_issue`, `wallet_pass_download`, `wallet_pass_revoke`를 서버 확인 결과 기준으로 기록한다.
- 수용 기준: 화면 제목과 메뉴 용어가 모두 `내 인증`이고 QR token, Wallet public ID, Apple authentication token, device push token 원문을 analytics·오류 메시지에 남기지 않는다. 비밀번호 변경 → 필수 약관 동의 → 본인 사진 게이트 우선순위를 Wallet 발급·갱신 route도 우회하지 않는다.

## `/settings` — 설정

- 목표·위계: 연결 정보 → 보안 → 계정 순으로 계정 변경 기능을 한곳에 모은다. 인증 카드 제시 화면과 계정 mutation 화면을 분리한다.
- 액션·흐름: 로그인한 회원은 일반 공용 화면의 헤더 오른쪽 톱니바퀴에서 진입한다. 설정 화면과 모바일 하단 탐색에서는 `내 정보`가 활성 상태다. 이메일 인증·본인 사진·비밀번호 변경을 열 때 설정 주소를 `returnTo`로 전달하고, 완료 후 설정으로 돌아온다.
- 경계·상태: member session과 canonical member profile만 사용한다. 비로그인은 설정 주소 전체를 보존해 로그인으로 이동한다. 비밀번호 변경 → 필수 약관 동의 → 본인 사진 필수 게이트 우선순위를 공용 layout에서 그대로 적용한다. 인증·복구·사진 제출 같은 집중 흐름에는 설정 아이콘과 모바일 하단 탐색을 표시하지 않는다.
- 반응형·분석: AOS·iOS 설정처럼 연결 정보·보안·계정 그룹의 전체 행 리스트를 사용하고, 회원 탈퇴는 별도 danger 그룹으로 분리한다. 320px에서 설명과 상태 badge가 줄바꿈되며 행 액션이 잘리지 않아야 한다.
- 수용 기준: 헤더 설정 아이콘은 로그인한 일반 회원 화면에서만 보이고 현재 경로를 안전한 내부 `returnTo`로 보존한다. `/settings`를 복귀 경로로 다시 중첩하지 않으며 외부 URL은 `/certification`으로 정제한다.

## `/settings/delete-account` — 회원 탈퇴 경고

- 목표·위계: 탈퇴 영향 안내 → 세션·혜택 중지와 개인정보 익명화 고지 → 최종 확인 → 탈퇴 처리 순이다. 설정 목록에서 즉시 계정을 삭제하지 않는다.
- 액션·흐름: 설정의 로그아웃 행은 앱 내 확인 모달을 먼저 열고, 회원 탈퇴 행은 이 경고 화면으로 이동한다. 경고를 확인한 뒤 `회원 탈퇴 계속하기`를 선택하면 최종 확인 모달이 열리고, 거기서만 탈퇴 API를 호출한다. 취소·뒤로 가기는 안전한 설정 주소로 돌아간다.
- 경계·상태: 로그인한 member session과 동일 출처의 탈퇴 API만 사용한다. 기본, 최종 확인, 탈퇴 처리 중, 실패, 완료 후 홈 이동 상태를 제공한다. 회원 식별자·세션 값은 화면과 오류 메시지에 노출하지 않는다.
- 반응형·분석: 360px에서는 안내 목록과 두 모달 액션을 한 열로 배치하고, 집중 흐름으로 하단 탐색과 설정 아이콘을 숨긴다. 다크 모드에서도 danger 표면과 본문 대비를 유지한다.
- 수용 기준: 로그아웃 또는 탈퇴가 클릭 후 무반응으로 끝나지 않고 명시적인 확인 단계가 나타난다. 탈퇴 API는 최종 확인 전 호출되지 않으며, 외부·중첩 복귀 주소는 `/settings`로 정제한다.

## `/certification/email` — 로그인·복구 이메일

- 목표·위계: 이메일 용도 안내 → 이메일 입력 → 코드 전송 결과와 고정된 대상 이메일 → 10분 유효시간 → 인증 완료 순이다. MM과 이메일은 서로를 대체하는 전환 상태가 아니라 각자의 접근 여정을 위한 별도 인증 수단으로 설명한다.
- 액션·흐름: primary는 인증 코드 전송과 인증 완료다. 코드를 보낸 뒤에는 대상 이메일을 일반 입력으로 수정할 수 없고 `다른 이메일 입력`을 명시적으로 선택해야 한다. 재전송은 전송 성공 후 60초 동안 비활성화하고 남은 시간을 표시한다. 완료하면 정제된 `returnTo`로 복귀한다.
- 경계·상태: member session과 서버의 이메일 중복·예약 식별자·발급 제한을 사용한다. 기본, 입력 검증 오류, 전송 중, 코드 입력, 코드 만료, 재전송 대기, 서버 오류, 완료 상태를 제공한다. 회원별 최신 `email_verify` challenge만 유효하고 메일 전송 완료로 표시되지 않은 challenge는 인증할 수 없다.
- 반응형·분석: 360px에서는 한 열과 full-width CTA를 사용하고 이메일 및 오류 문구가 수평 overflow를 만들지 않는다. 인증 코드 유효시간은 `mm:ss`, 재전송 대기시간은 남은 초 단위로 실시간 갱신하며 보조기술에도 timer로 전달한다. 이메일 원문과 인증 코드는 analytics·활동 로그에 남기지 않는다.
- 수용 기준: 전송 후 이메일이 고정되고, 10분이 지나면 인증 버튼이 비활성화되며, 60초 전에는 UI와 서버 모두 재전송을 거절한다. 새 코드를 발급하면 이전 이메일·이전 코드가 즉시 무효화되고, 성공 후 설정 화면에는 인증된 이메일 상태만 요약해서 표시한다.

## `/coupons` — 내 쿠폰

- 목표·위계: 사용 가능 쿠폰 수 → 사용 가능 목록 → 사용/만료 조건 → 지난 쿠폰 순이다.
- 액션·흐름: 카드 상단에서 쿠폰 조건을 펼치거나 접고, `사용하기`는 아코디언 상태와 무관하게 카드 하단에 유지한다. 카드 상단의 제휴처명으로 연결 제휴처 상세를 연다. 사용자 메뉴와 상세에서 진입한다.
- 경계·상태: 로그인 회원에게 발급된 쿠폰만 repository로 조회한다. 사용 가능, 빈 상태, 만료, 사용 완료, 로딩, 오류, 비로그인을 제공한다.
- 반응형·분석: 모바일은 accordion 한 열, 넓은 화면도 이용 조건의 읽기 순서를 유지한다. `coupon_wallet_view`, `coupon_expand`, `coupon_use`를 기록한다.
- 수용 기준: 만료·사용 완료 쿠폰이 primary로 오인되지 않고 제휴처 이동 시 상세 접근 권한을 다시 검증한다.

## `/notifications` — 내 알림

- 목표·위계: 미확인 수 → 중요·최신 알림 → 읽은 알림 → 수신 설정 순이다.
- 액션·흐름: primary는 알림 목적지 열기, 보조는 읽음 처리와 수신 설정이다. 사용자 메뉴·push에서 진입한다.
- 경계·상태: 현재 member audience 알림만 API로 조회한다. 기본, 빈 상태, 더보기, 읽음 처리 중, 일부 실패, 비로그인을 제공한다.
- 반응형·분석: 모바일은 compact row, 데스크톱은 목록과 설정을 분리한다. `notification_inbox_view`, `notification_open`, `notification_mark_read`를 기록한다.
- 수용 기준: 알림 링크는 허용된 내부 목적지만 열고 읽음 실패 시 항목 상태를 복구하며 긴 한국어 제목이 액션을 밀지 않는다.
