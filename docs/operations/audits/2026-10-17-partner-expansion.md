# 출품 리뷰 기반 제휴처 확대 운영 검토안과 접수 경로 확인

이 파일은 [Issue #606](https://github.com/MyKnow/ssartnership/issues/606)의 조사·계획 산출물이다. Durumari 프로젝트 `fb4f797c-811a-491a-b06e-697f6929743d`의 Context `76bb96e0-4d30-459a-80de-047a8412e7b5` revision 1을 저장소 리뷰용으로 보존한 시점 사본이며, 이후 운영 결정은 서버 Context에서 확인한다. `completed`는 이 보고서의 조사·작성 완료를 뜻하며 실제 수요 조사·연락·제휴 체결 완료를 뜻하지 않는다.

## 요청과 범위

#606은 출품 리뷰 “제휴처가 앞으로 더 많이 늘어나길”에 대한 운영 계획이다. 사용자 요청은 남은 개선 구현과 작업별 dev PR·Preview 전달이며, 외부 업체 연락·계약·비용 집행은 이 계획의 실행 범위가 아니다. 이 Context는 운영 검토안이며 실제 제휴 체결을 뜻하지 않는다.

## 선별 기준과 원장

운영자(MyKnow)가 기존 수신함에서 두 성공 로그와 대응하는 실제 제안의 도착·중복·스팸·처리 상태를 확인한다. 원문과 연락처는 제한된 수신함에 유지하고 공개 Issue/Context에는 비식별 후보 ID와 집계만 기록한다. 로그가 적어 원문 존재 여부·누락 수를 단정하지 않는다.

기존 회원 피드백 접수 채널에서 최근 30일의 캠퍼스·이용 장면·원하는 혜택·빈도·가격 민감도를 익명 집계한다. 모집/설문 발송은 운영자가 문항과 경로를 검토한 뒤 별도로 실행한다. /suggest는 사업자 제안이며 회원 수요 설문으로 대체하지 않는다.

후보 원장 최소 필드: 후보ID, 분류, 캠퍼스/생활권, 출처·관측 기간, 독립 요청 수(확인 불가면 미측정), 기존 대안과 차이, 제안 혜택과 조건, 담당 역할, 상태, 마지막 확인일, 다음 행동·기한, 검토 결과·보류 이유. 연락처/원문 링크는 공개 원장에 넣지 않는다.

진입 조건: 중복 제거한 실제 수요 또는 검증 가능한 접수 제안, 기존 제휴 대비 공백, 대상/지점/기간/인증/제외 조건, 운영 부담을 확인. 불명확하면 보류.

비교 점수는 검토안: 수요 근거0~3, 기존 공백0~2, 혜택 실효성0~2, 접근성0~2, 운영 단순성0~1(총10). 미측정을0점/수요 없음으로 치환하지 말고 점수 보류. 동점은 검증된 요청과 운영 비용으로 비교하며 점수만으로 연락·계약을 승인하지 않는다.

## 상태·책임·첫 실행 순서

흐름은 수요 확인 대기 → 내부 검토 → 연락 승인 대기 → 협의 → 조건 검증 → 등록 검수 → 공개, 또는 보류/종료다. 이번 작업은 앞의 내부 검토까지 진행하는 계획 작성과 근거 확인이다. 연락 승인 전에는 업체에 메시지를 보내지 않는다. 협의 이후 공개까지는 기존 파트너 등록/관리 경로와 공개 권한·검수 절차를 따른다.

책임 역할은 운영 책임자 MyKnow(수요/후보 선정·연락/조건 승인), 입력/집계 담당(운영자가 지정; 미지정 시 MyKnow), 게시 검수 담당(등록 권한이 있는 관리자)이다. AI는 읽기 집계·초안·중복 탐지 보조이며 연락/약속/게시 권한을 추정하지 않는다.
첫 운영 주기는 다음 순서를 권고한다. 일정은 계획 수락 시점을 기준으로 한 운영자 검토안이며 아직 수락·실행되지 않았다.

| 시점 | 담당 | 다음 행동 | 남길 결과 |
| --- | --- | --- | --- |
| 2영업일 이내 | 운영 책임자 | 기존 수신함 접수 상태 확인·중복 제거·후보화 | 수신/처리 상태 집계와 비식별 후보 원장 |
| 7일 이내 | 입력/집계 담당 | 최근 30일 수요 표본과 기존 제휴 공백 대조 | 근거·미측정 항목·분류별 조사 결과 |
| 14일 이내 | 운영 책임자 | 근거가 있는 상위 최대 3건 내부 검토·연락 여부 결정 | 연락 승인 또는 보류 이유와 다음 행동 |

증거가 없으면 0건이어도 원인과 다음 조사만 기록한다.

## 측정과 완료 기준

현재 공급 기준선은 공개32/기간 내29; 접수 신호 기준선은 잔존 suggest_submit2, 고유·미처리·계약 전환·수요는 미측정. 향후 주간 KPI는 후보 중 근거/조건 필수 항목 충족 비율, 수요 확인→내부 검토 건수, 연락 승인→회신/조건 확정/공개 전환 건수, 단계별 대기일, 공개 후30일 이용 가능할 때의 혜택 이용/조건 문의를 따로 측정한다. 표본과 관측 기간을 함께 쓰고 없는 계측은 미측정으로 둔다. 첫 운영 주기 후 기준선을 확정하며 임의 매출·제휴 수 목표는 두지 않는다.

#606 산출물 완료 기준은 분포·접수 경로·수요 한계를 검증하고 후보/담당/상태/조건/다음 행동과 KPI를 실행 가능한 계획으로 남기는 것이다. 실제 수요 검증·외부 협의·제휴 체결 완료와 구분한다. Git/PR/Preview 전달 및 Issue 종료 판단은 root 담당자가 별도 확인한다.

## 확인 결과와 한계

- Production에는 읽기 요청만 수행했다. 원문·개인정보·환경 변수 값은 보고서에 저장하지 않았다.
- 공개 카탈로그 32행을 전부 읽었고 기간 내 분류 합계 29와 대조했다. 캠퍼스는 중복 집계이며 서로 합산하지 않는다.
- 성공 이벤트 exact count와 created_at 조회 결과가 모두 2건인 것을 대조했다. 시도 제한 테이블을 제안 접수 수로 사용하지 않았다.
- 제안 메일의 도착·후속 처리 상태 및 회원 수요는 확인하지 않았다. 따라서 업체별 확정 shortlist나 미처리 수를 만들지 않았다.
- 제품 UI·실행 코드·스키마를 변경하지 않는 보고서이므로 렌더 검증 대상이 없다. 문서 검증과 차이 기반 검증 결과는 전달 시 별도 기록한다.
